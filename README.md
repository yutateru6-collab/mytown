# MYTOWN 直方

「直方のこと、これ1個見ればだいたい分かる。」を目指す、非公式の地域生活アプリMVPです。

## 現在の2本柱

### 1. 暮らしから入る「今日の直方」

直方市の公式公開情報を約2時間ごとに確認し、新着、人口、ごみ、市議会日程、交通、イベント等を生活者の言葉で表示します。市報の最新号も自動検知し、公式ページ・PDF・ページ見出しを表示します。

### 2. 徹底的に見える化する「市長・議会」

政治を隠さず、ただし前提知識も要求しません。

- 現在の市長と公式資料で確認できる経歴
- 市議会議員19人の一覧
- 議長・副議長
- 常任委員会・議会運営委員会
- 2026年6月定例会の一般質問
- 8会派
- 次の直方市長選・市議会議員選挙の任期満了日
- 政務活動費
- 「年度」「会派」「一般質問」「議案」「採決」等の政治ことば図鑑

を専用タブで確認できます。

## 説明のルール

MYTOWNは「専門用語を知っている前提」を置きません。

必ず、

1. 普通の言葉
2. 小学生でも分かる説明
3. ちょっと市民目線の「まちナビ」解説
4. 正式名称
5. 実際の直方の例
6. 一次資料

の順で理解できるようにします。

例:

- **年度** → 「4月から次の3月までの1年」
- **会派** → 「議会の中のチーム」
- **一般質問** → 「議員が市長や市役所に『これどうなってる？』と公開で聞く時間」
- **常任委員会** → 「テーマ別に詳しく見る議員のチーム」
- **政務活動費** → 「議員が調査・研究などに使う公費。給料とは別」
- **任期満了日** → 「今の役職の期間がいったん終わる日。投票日とは限らない」

特に年度は、**2026年度 = 2026年4月1日〜2027年3月31日** のように日付まで書きます。

## 「まちナビ」の立ち位置

案内役は政治家を評価しません。

ユーモアの対象は、人ではなく「分かりにくい制度や役所語」です。

例:

> 🦖「議決と採決、似すぎ問題。採決は投票する動き、議決はその結果。」

事実は中立に保ちながら、疑問は市民目線で出します。

- で、何が変わる？
- なんで？
- いくら？
- 誰が決めた？
- 誰が質問した？
- 誰が賛成・反対した？

## 透明性のルール

「公式ページにある」だけでは最新とは限りません。

例として会派は、現在の「市議会のしくみ」では8会派と確認できますが、所属議員一覧のページには **2023年5月16日現在** と明記されています。

MYTOWNではこのズレを隠さず表示し、古い基準日の所属を「現在確定」と断定しません。

また、議員名簿に期数・職歴がない場合は、推測で埋めず、

> 現行の公式名簿では確認できません。過去の選挙結果等で裏付けできたものから追加します。

と表示します。

## 自動同期・再検証

`.github/workflows/sync-nogata.yml` が約2時間ごとに実行されます（GitHub Actionsの予約実行のため、時刻は前後することがあります）。

処理:

1. 直方市の一次情報を取得
2. `data/latest.json` と `data/bulletin.json` を更新
3. 市議会日程など高リスク情報を再検証
4. `data/politics.json` の市長・議員・会派・委員会・選挙・政務活動費・一般質問を公式ページと再照合
5. 市報の最新号、ページ別PDF、公式ページ上の見出しを検知（記事内容の要約は確認待ち）
6. JSONを検証
7. 変更がある場合だけGitHubへ自動コミット

政治データが公式ページと一致しなくなった場合、検証を成功扱いにしない設計です。

## 画面

- `きょう` — 暮らし・新着・議会・人口など
- `場所` — 場所を確認できる情報
- `見つける` — 普通の言葉で検索
- `市長・議会` — 市長、議員19人、会派、委員会、選挙、お金、ことば図鑑
- `聞く` — 同期済み公式情報を普通の言葉で質問
- 詳細 — `これ何？ → なんで？ → いくら？ → 誰が決めた？`

## 最重要原則

**事実は曲げない。説明は固くしない。前提知識は要求しない。**

資料を置くだけでは透明化ではありません。

公開されている情報を、普通の市民が「へえ、そういう意味なん」と理解できるところまで翻訳して初めて、MYTOWNの透明化と考えます。
