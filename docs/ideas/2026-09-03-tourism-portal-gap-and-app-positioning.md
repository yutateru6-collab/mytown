# 調査メモ：直方市観光ポータルとの差別化と「のおがた日和」の勝ち筋

- 作成日: 2026-09-03
- ステータス: proposed
- 優先度: P0
- 対象: MYTOWN / のおがた日和
- 比較対象: https://nogata-kankoh.com/

## 結論

直方市観光ポータルは、直方の観光資源を魅力的に紹介する「旅のカタログ」として強い。

「のおがた日和」は同じものを作って競争してはいけない。

目指す位置は次の通り。

> 観光サイトが「直方に何があるか」を教えるなら、のおがた日和は「今日、あなたに何が関係するか」を教える。

観光サイトを置き換えるのではなく、観光サイトを含む行政・地域団体・施設・商業施設などの情報の上に、

- 今
- 近く
- 自分向け
- まだ間に合う
- 次に何をすればよいか
- 情報が確かか

を判断できる層を作る。

最終的な競争力は「情報量」ではなく、**市民が今日の行動を決められること**と、**情報が古い・不確かな場合にそれを正直に示せること**に置く。

---

## 1. 直方市観光ポータルの強い点

### 1-1. 直方の魅力を見せる編集力

トップは「直方市で旅しよう」「チルして満ちる、わたしのココロ」という観光向けの世界観で統一されている。

グルメ、景色、歴史、伝統文化、花、鉄道など、直方を知らない人にも魅力が伝わる構成になっている。

### 1-2. 観光資源の蓄積量

2026年9月3日の公開ページ確認時点で、主な一覧には次の件数表示があった。

- 見る・遊ぶ・買う: 44件
- 食べる: 76件
- 年間イベント: 13件
- 会員情報: 53件

飲食店や観光スポットの個別ページには、住所、電話、営業時間、定休日、駐車場、公式サイト・SNSへのリンクなど、訪問前に必要な基本情報がある。

### 1-3. 歴史・鉄道の読み物が充実

単なる店舗一覧だけでなく、東蓮寺藩、城下町散策、石炭輸送と鉄道の歴史、SL保存活動など、直方の背景を学べる長い読み物がある。

これは「直方を好きになる」ための素材として非常に価値が高い。

### 1-4. 観光案内としての補助導線

- Instagram / Facebook
- 観光PR動画
- 多言語電子ガイドブック
- アクセス案内
- 宿泊情報

が用意されている。電子ガイドブックは10言語対応、文字拡大・音声読み上げ対応と案内されている。

### 1-5. 新着記事は更新されている

2026年の「直方隕石」一般公開、直方夜市、バスツアー、高校生まち歩き、球根植えボランティアなど、当年の情報更新は確認できる。

したがって、サイト全体が放置されているわけではない。

## 2. 観光サイトに不足しているもの

ここで挙げる点の一部は欠陥ではなく、観光ポータルという役割上の限界である。「のおがた日和」は、その役割の外側を埋めるべきである。

### 2-1. 「今の自分」に合わせた入口

現在の主分類は、見る・遊ぶ、食べる、イベント、工芸品、歴史、鉄道、宿泊などのカタログ型である。

しかし市民の実際の疑問は、次のような状況型である。

- 今日、子どもとどこに行ける？
- 今から行ける無料イベントは？
- 家から15分以内で何かある？
- 雨でも行ける？
- 申し込みはまだ間に合う？
- 駐車場はある？
- ベビーカーで行ける？
- 今日営業している？

観光サイトには情報の素材はあるが、ユーザーの現在時刻・場所・家族構成・関心に合わせて組み替える層は確認できなかった。

### 2-2. 年間案内と最新記事の鮮度が分かれている

年間イベントページは、2026年9月時点の公開ページでも「チューリップフェア2025」の開催日を表示していた。一方、新着記事には2026年のイベントが掲載されている。

この状態では、ユーザーが次を判断しにくい。

- これは今年の情報か
- 毎年ある行事の一般説明か
- 現在参加できるのか
- 受付が終了したのか

「のおがた日和」では、文章をそのまま並べず、年・開催状態・申込状態を別項目として正規化する必要がある。

### 2-3. 「開催予定」と「申込受付中」が分離されていない

イベントは開催日が未来でも、申込期限を過ぎている場合がある。

必要な状態は少なくとも次の2軸である。

```text
開催状態:
scheduled / changed / postponed / cancelled / ended / unconfirmed

申込状態:
not_required / not_open / open / closing_soon / closed / full / unknown
```

タイトルに「受付中」と書かれていても、期限の日付が過ぎたらアプリ側では「受付終了」とする。矛盾があれば自動公開せず、確認待ちにする。

### 2-4. 情報源が一か所に集まらない

観光協会のサイトだけでは、次の情報を網羅できない。

- 直方市公式
- 社会福祉協議会
- NPO・地域団体
- 公共施設
- 商業施設
- 学校
- 商店街
- 小規模な主催者
- ボランティア募集
- 市民意見募集

「のおがた日和」の価値は、各サイトより詳しい記事を書くことではなく、**ばらばらの一次情報へ一つの入口から到達できること**にある。

### 2-5. 保存・通知・カレンダーという行動支援

公開ページ上では、イベントの保存、締切前通知、地域・関心別通知、カレンダー追加を中心とした継続利用導線は確認できなかった。

イベントを見つけるだけで終わらず、次まで一続きにする。

```text
見つける
→ 自分向けか判断する
→ 保存する
→ 締切前に通知
→ カレンダーへ追加
→ 当日の変更を確認
→ 終了後に関連イベントを知る
```

### 2-6. 日常生活・行政との接続

観光サイトは旅・外出の魅力を扱う。市民が毎日必要とする次の情報は役割外である。

- ごみ
- 道路工事・通行情報
- バス等の変更
- 防災
- 公共施設
- 申請期限
- 補助・給付・行政手続き
- 市報
- 市議会
- 予算
- 意見募集

ここをイベントと同じホームに自然に混ぜることが、「毎日開く理由」になる。

### 2-7. 「なぜ」「誰が」「いくら」の説明

観光サイトは、場所・イベントの魅力を伝えるのが中心である。

「のおがた日和」は、生活上の出来事から次へ掘れることを独自価値にする。

```text
このイベント・施設・工事は何？
→ なぜ行う？
→ 誰が主催・発注した？
→ 公費が入る場合はいくら？
→ どの予算・計画と関係する？
→ 誰が議論し、いつ決まった？
→ 原文はどこ？
```

### 2-8. 主催者・市民からの専用投稿窓口

公開範囲で確認できたのは一般的な問い合わせフォームだった。イベント名、開催日、場所、主催者、申込URLなどを構造化して受け付ける専用投稿フローは確認できなかった。

「のおがた日和」は自由掲示板にせず、URLだけでも送れる情報提供フォームと、確認後に公開する審査フローを作る。

### 2-9. 情報衛生上の細部

公開インデックスには「未分類」内の2024年「test」投稿が残っていた。また、一覧で観光スポットにも「店舗情報はコチラ」という共通文言が使われている。

大きな問題ではないが、「何を押すと何が開くか」の明確さや、古いテスト情報を検索結果に残さない運用は改善余地がある。

## 3. 「のおがた日和」が取るべき立ち位置

### 観光サイト

**直方の魅力を見つけ、行きたいと思わせる。**

### のおがた日和

**今日の直方を、自分に関係する順に並べ、行動できるようにする。**

### 競争ではなくレイヤー化

観光協会の記事・スポット情報は重要な一次情報源である。

「のおがた日和」は以下を行う。

1. 観光サイトの記事を公式情報源として参照
2. 他の情報源と重複統合
3. 日時・場所・費用・締切・状態を構造化
4. 現在地・地域・関心に応じて並べ替え
5. 元ページへ正しく送客
6. 情報が古い・矛盾する場合は警告

これにより、観光協会と競合するより、観光協会の情報がより多くの市民へ届く補助線になる。

---

## 4. 全員に同じ機能を使わせない

「みんなが毎日同じ理由で使う」は現実的ではない。

各層に一つ以上の強い利用理由を作り、ホームを個人化する。

| 利用者 | 主な利用理由 |
|---|---|
| 子育て世代 | 今日・週末の親子イベント、ごみ、学校・施設、締切 |
| 高校生・若者 | 無料イベント、音楽、店、ボランティア、地元の知らない場所 |
| 会社員 | 今週末、帰宅時の交通・工事、期限、短時間で読める市の動き |
| 高齢者 | バス、健康・交流イベント、施設、電話問い合わせ、読みやすい表示 |
| 観光客 | スポット、飲食、歴史、ルート、現在地から近い場所 |
| 政治に関心がない市民 | 生活情報を見た流れで「なぜ」「誰が決めた」を知る |

## 5. 最優先の3つの利用ループ

### 5-1. 毎日の生活ループ

```text
アプリを開く
→ 今日見ておく3件
→ ごみ / 近く / 締切・変更
→ 必要なものだけ詳しく見る
```

ホーム上部は情報を詰め込みすぎず、最重要3件を小さく表示する。

### 5-2. 外出・イベントループ

```text
今日なにする？
→ 今日 / 今週末 / 親子 / 無料 / 近く
→ 日時・距離・費用・申込状態を比較
→ 保存・カレンダー追加
→ 元の主催者ページで最終確認
```

### 5-3. 街を理解するループ

```text
この工事・施設・制度なに？
→ 30秒で概要
→ なぜ？
→ いくら？
→ 誰が決めた？
→ 3分解説
→ 一次資料
```

この3ループを一つのホームに載せるが、政治情報を最上段で強制しない。

## 6. 現行GitHub実装の良い点

コード上では、すでに次の方向が実装されている。

- 観光協会、社会福祉協議会、イオンモール直方、NPOの横断収集
- 同一イベント候補の重複排除
- 開催日の近い順の表示
- 今日、今週末、親子、地域参加、無料、スポーツ、学びの絞り込み
- 情報源の偏りを抑えたホーム3件選出
- 情報源の取得状態と最終更新の表示
- 「すべてのイベントを網羅していない」ことの明示
- 今日の新着、締切、ごみをまとめた短いブリーフィング
- 市報、制度、地図、市議会、質問機能との接続

方向は正しい。次の勝負は、情報源を増やすことだけではなく、**抽出結果を行動に使える正確さまで上げること**である。

## 7. 現行データで見つかった重大な注意点

### 7-1. 取得成功と内容の正しさは別

`sourceHealth: ok` は、通信・解析処理が完了したことを示すだけで、各項目が正しく抽出された保証にはなっていない。

2026年9月3日生成の `data/community-events.json` で、以下を確認した。

#### 例A：申込期限を過ぎたイベント

観光協会のバスツアーは、元ページに「8月31日申込期限」「5,000円」とある。

しかし9月3日生成データでは、タイトルに「申込み受付中」が残り、`status: scheduled` のまま、`applicationDeadline` と `money` が入っていない。

開催予定であることと、申込可能であることを混同すると、ユーザーが行動を誤る。

#### 例B：金額の不正値

10月31日の高校生まち歩きイベントに `money: "000円"` が保存されている。別の公開記事では参加費1,000円と確認できるため、少なくとも現在の値は利用者へ表示してはいけない。

さらに、`editoriallyReviewed: true` の既存項目を優先してマージする現在の仕組みでは、一度保存された誤値が後続の自動抽出より優先され続ける可能性がある。

### 7-2. 必要な改善

`sourceHealth` を次の二つに分ける。

```text
fetchHealth:
  ok / stale / error

semanticHealth:
  verified / partial / conflict / invalid / needs_review
```

イベント単位だけでなく、重要項目単位で状態を持つ。

```text
moneyStatus
applicationDeadlineStatus
locationStatus
dateStatus
registrationStatus
```

### 7-3. 自動公開を止める条件

次のいずれかに該当する情報は、ホームのおすすめ・締切カードから除外し、管理確認へ送る。

- 金額が `000円` など不自然
- タイトルの「受付中」と期限計算が矛盾
- 開催日より申込開始日が後
- 申込期限が開催日より後で、元資料に説明がない
- 年がない日付を現在年として補った結果、曜日が一致しない
- 同じ情報源内で開催日が複数矛盾
- 会場が市外なのに直方市内イベントとして分類
- 元ページの更新年とイベント年が大きくずれる

### 7-4. 推奨する追加データ項目

```text
sourcePublishedAt
sourceUpdatedAt
lastCheckedAt
eventStatus
registrationStatus
applicationStarts
applicationDeadline
registrationUrl
registrationMethod
cancelledAt
fieldSources
fieldConfidence
needsReview
reviewReasons
reviewedAt
reviewedBy
```

`fieldConfidence` はユーザー向け点数評価ではなく、内部の公開可否判定に使う。

## 8. 差別化機能の優先順位

### P0：信頼できる「今日の直方」

- 今日見ておく3件
- ごみ
- 今日・明日のイベント
- 締切・変更
- 情報元
- 元ページの更新日
- アプリの最終確認時刻
- 不明・矛盾時の警告

### P0：イベントの状態正規化

- 開催状態と申込状態を分離
- 期限を過ぎたら自動で受付終了
- 中止・延期・満員・変更を扱う
- 静的な年間行事説明と当年開催情報を分離

### P0：複数情報源の横断集約

- 観光協会
- 市公式
- 社協
- 商業施設
- 文化施設
- NPO・地域団体

一覧の件数より、異なる情報源を一つの画面で比較できることを優先する。

### P1：近く・今からの判断

- 現在地または指定地域
- 距離
- 今日
- 今から行ける
- 雨でも可
- 無料
- 親子
- 駐車場
- バリアフリー

確認できない項目は空欄にし、推測で付けない。

### P1：保存・通知・カレンダー

- お気に入り
- 申込締切前通知
- 開催前通知
- 中止・変更通知
- `.ics` カレンダー追加

### P1：主催者・市民投稿

- URLだけで情報提供
- 主催者向け最小入力
- 自動抽出後に本人が確認
- 管理者の承認後に公開
- 自由掲示板にはしない

### P1：生活から市政へ

- 工事・施設・制度カードに「なぜ？」
- 予算・計画・議案との関連
- 市長・市議会・担当部署の役割
- 30秒 → 3分 → 原文

## 9. ホームの理想的な情報順

```text
1. 今日、見ておくこと（小さな3件）
   ごみ / 変更・新着 / 締切

2. 直方で、なにする？
   今日 / 今週末 / 親子 / 無料
   近い日から最大3件

3. 暮らしから探す
   地図 / 制度・手続き / 市報 / 交通

4. 今日の直方を1つ知る
   30秒解説 / 次の市議会

5. 参加する
   イベント / ボランティア / 意見募集

6. まちナビに聞く
```

政治情報は消さないが、日常の役立ちを先に置く。

| 市民の質問 | 観光ポータル | のおがた日和の役割 |

| 直方に何がある？ | 強い | 横断検索して元ページへつなぐ |

## 11. やってはいけないこと

- 観光サイトの文章・画像を無断でコピーして別サイト化する
- もう一つのイベント一覧を作るだけで終わる
- 件数を増やすために日付不明・出典不明の投稿を載せる
- `sourceHealth: ok` を「内容確認済み」と表示する
- 期限切れの「受付中」をそのまま表示する
- 情報のないバリアフリー・対象年齢・料金を推測する
- ホームを政治ニュースで埋める
- すべての市民に同じ情報を表示する
- 自由投稿を無審査で公開する

## 12. 完了条件

### データ

- 申込期限を過ぎたイベントが「受付中」にならない
- 不正な金額を自動公開しない
- 開催状態と申込状態が別々に表示される
- 各イベントに情報元・最終確認時刻がある
- 期限・料金・場所の出典を追跡できる
- 年間の一般説明と当年情報を区別する
- 情報源の通信成功と内容検証を区別する

### UX

- 初見の利用者が10秒以内に「今日の自分に関係する情報」を1件見つけられる
- イベント詳細を開かずに、開催日・場所・費用・申込可否を判断できる
- 2タップ以内で元の主催者ページへ行ける
- 現在地を許可しなくても地区指定で使える
- 政治に興味がない人が、生活情報から自然に「なぜ？」へ進める

### 成功指標

- 週次継続率
- 今日の3件の閲覧率
- イベント保存率
- 申込・主催者ページ到達率
- 締切前通知からの行動率
- 「行ったら終了・中止だった」報告率
- 情報の誤り報告率
- 観光協会等の一次情報源への送客数
- 「このアプリだけで直方の予定を探せた」という回答率

## 最終方針

観光サイトより写真を豪華にすることや、店舗数で上回ることは主戦場ではない。

「のおがた日和」の強みは、

> ばらばらの直方情報を集め、古い・新しい・受付中・終了を整理し、今日の自分に関係する順で見せ、そのまま行動につなげること。

さらに生活上の疑問から、行政・予算・市長・市議会・議員まで自然につなぐ。

これにより、観光ポータルが「直方を訪れたくなる場所」、のおがた日和が「直方で暮らすなら毎週開く場所」という役割分担を作る。
