# 実装検討メモ：直方イベント全部入りハブ

- 作成日: 2026-09-02
- ステータス: candidate
- 優先度: P0
- 対象: MYTOWN

## ひとことで

直方市内で行われるイベント情報を、行政・観光・商工・文化施設・商業施設・地域団体・店舗・学校・SNSなどから集約し、MYTOWNを見れば「直方で何があるか」が一か所で分かる状態を目指す。

単なるイベント一覧ではなく、直方の情報流通インフラを作る構想。

## なぜ必要？

現在の直方では、イベント主催者ごとに情報発信先が分かれている。

例：
- 直方市公式サイト
- 直方市観光ポータル
- 直方商工会議所
- ユメニティのおがた
- 直方谷尾美術館
- イオンモール直方
- 地域情報サイト
- 各団体・店舗・個人のInstagram / Facebook等

主催者側は発信していても、市民側がそのアカウントをフォローしていなければ情報が届かない。

MYTOWNが「直方のことはここを見ればだいたい分かる」入口になることで、この分断を解消する。

## 重要な前提

「SNSを全部自動スクレイピングすれば完成」という設計にはしない。

Instagramの公式APIは、プロアカウント（Business / Creator）中心で、一般の個人アカウントを自由に横断取得できるAPIではない。SNS各社の仕様変更・API制限・利用規約にも左右される。

そのため、収集方法は1本ではなく次の3本立てにする。

1. **自動収集**：公式Webサイト・RSS・APIなど、安定して取得できる情報
2. **主催者投稿**：イベント主催者がMYTOWNへ直接登録
3. **市民からの情報提供**：見つけたイベントURL等を送ってもらい、確認後に掲載

これで「自動化率」ではなく「取りこぼし率を下げる」ことを目標にする。

## 現時点で確認できる主要な情報源候補

### A. 自動収集を優先する候補

- 直方市公式ホームページ
- 直方市公式RSS
- 直方市観光ポータルサイト
- 直方商工会議所
- ユメニティのおがた
- 直方谷尾美術館および関連施設
- イオンモール直方イベントページ

### B. 提携・利用条件を確認して候補にするもの

- チクスキ等の地域イベント掲示板
- 地域メディア
- 各商店街・地域団体
- 学校・PTA等

他社メディアの情報は、公開ページだからという理由だけで全文転載・無断再配信しない。利用規約・robots・著作権・データ利用条件を確認し、必要なら連携・掲載許可を取る。

### C. SNS中心の団体・店舗

- Instagramのみでイベント告知する団体
- Facebookのみで告知する団体
- 店舗アカウント
- 小規模サークル
- 個人主催イベント

ここは「全部自動取得」を目指さず、主催者登録・URL投稿・公式APIでのオプトイン連携を組み合わせる。

## 推奨アーキテクチャ

既存MYTOWNには、直方市公式情報を6時間ごとに取得するGitHub Actionsの同期処理がある。

ただし現在の `data/sources.json` は直方市公式ドメインを中心とした厳密な市政データ用なので、イベントを同じパイプラインに混在させない。

### 新設候補

```text
data/event-sources.json
scripts/sync_events.py
scripts/verify_events.py
data/events.json
.github/workflows/sync-events.yml
```

### `event-sources.json`

イベント情報源を管理する専用レジストリ。

例：

```json
{
  "id": "nogata-tourism",
  "name": "直方市観光ポータル",
  "type": "html",
  "url": "...",
  "sourceClass": "official_or_primary",
  "refreshHours": 3,
  "enabled": true
}
```

## 情報の信頼度

同じイベントについて複数情報源が矛盾する場合に備えて、情報源に優先順位を持たせる。

基本例：

1. 主催者本人・主催団体の公式発表
2. 会場の公式発表
3. 直方市等の公的機関
4. 公式パートナー・後援団体
5. 地域メディア
6. 市民投稿

ただし、機械的な順位だけで確定せず、キャンセル等の新しい情報を優先できるよう更新日時も見る。

## 重複イベントの統合

同じイベントが市・観光・Instagram・イオン等に複数掲載される可能性がある。

重複候補判定：

- 開催日
- 会場
- 主催者
- タイトル類似度
- 元URL

同一イベントと判定できたら1枚にまとめ、下部に「確認できた情報源」を複数表示する。

これにより、同じ夏祭りが4件並ぶ状態を避ける。

## 主催者投稿機能

MYTOWNのイベント集約を成功させる最大の鍵。

主催者にとって「もう一つSNSを更新する作業」にしてはいけない。

### 理想

ホームまたはイベント画面に

**「イベントを載せる」**

を置く。

入力は最小限：

- イベント名
- 日時
- 場所
- 主催者
- 詳細URLまたはSNS投稿URL
- 画像（任意）

SNSの投稿URLを貼るだけで、可能な範囲の項目を自動補完し、主催者が確認して送信できる形を目標にする。

### 掲載メリットを主催者に与える

- 無料掲載
- 市民に届く
- イベントカードが自動生成される
- MYTOWNカレンダーに載る
- 地図に載る
- 開催前通知の対象になる
- 元のInstagram等へ送客する

MYTOWNがSNSの代わりになるのではなく、各SNSへの「ハブ」になる。

## 市民からの情報提供

ボタン：

**「このイベントも載せて！」**

市民はURLだけでも送れるようにする。

市民投稿はそのまま公開せず、

- URL確認
- 開催日・場所確認
- 主催者確認
- 重複確認

を通してから掲載。

誤情報・いたずら・営利スパム対策が必要。

## SNS連携の考え方

### Instagram

Instagram APIはプロアカウント中心。すべての公開個人アカウントを自由に巡回できる前提にしない。

現実的な方法：

- MYTOWNと連携したい主催者がオプトインする
- 主催者自身の公式アカウント情報を取得する
- MYTOWNへのメンション・指定ハッシュタグ等を利用できる範囲で検討
- APIで取れない団体は投稿フォームへ誘導

### その他SNS

Facebook、X、LINE等もAPIや規約が変わり得るので、「そのSNSから必ず取得できる」ことをMYTOWNの根幹にしない。

SNSは入口の1つと位置づける。

## カレンダー

- 今日
- 明日
- 今週末
- 月間

の切り替え。

将来的にはGoogle / Appleカレンダー追加用のiCalendar (`.ics`) 出力を検討。

## 通知

ユーザーが興味カテゴリを選べる。

例：

- 子ども向けイベントだけ
- 直方駅周辺だけ
- 無料イベントだけ
- お祭りだけ

「全部通知」は通知疲れになるため避ける。

## 中止・変更対応

イベントハブの信用は「載っている数」より「行ったら中止だった」を減らせるかで決まる。

開催直前のイベントほど再確認頻度を上げる設計を検討。

例：
- 30日以上先：1日1回
- 7日以内：6時間ごと
- 48時間以内：1〜3時間ごと

GitHub Actionsは実行時刻に遅延する場合があるため、即時性が重要になった段階ではCloudflare Cron等も検討する。

## 投稿受付のバックエンド

現在のMYTOWNは静的配信中心なので、一般市民・主催者から投稿を受けるには書き込み用バックエンドが必要になる。

### MVP

外部フォームまたは簡易受付フォームでスタートしてもよい。

### 本命

Cloudflare Workers + D1等で

```text
submission
→ moderation queue
→ approved event
→ public API / events.json
```

の流れにする。

クライアント側にGitHubトークン等の秘密情報は置かない。

## 管理画面

将来必要。

- 新規投稿確認
- 重複候補
- 日付抽出失敗
- 中止候補
- 情報源エラー
- スパム報告

人間が全部入力するのではなく、「AI・プログラムが候補を作り、人が怪しいものだけ確認」する。

## AIを使う部分

AIは情報を捏造する用途ではなく、整理補助に限定する。

候補：

- 告知文から日時・場所・料金等を抽出
- 長い告知を短く要約
- カテゴリ候補を付ける
- 重複候補の判定補助

重要項目（日付・会場・料金・中止等）は元情報との突合を必須にする。

## 先に解決すべき問題

- [ ] 各サイトの利用規約・robots・再利用可否を確認
- [ ] 画像の転載権利を確認。原則は元サイトへのリンクまたは許諾済み画像を使う
- [ ] 各サイトごとにHTML構造変化への耐性を設計
- [ ] SNS APIの最新仕様を実装時に再確認
- [ ] 重複統合ロジックを設計
- [ ] 中止・延期の反映方法を設計
- [ ] 主催者本人確認の方法を決める
- [ ] 営利イベント・政治イベント・宗教イベント等の掲載基準を文章化
- [ ] 誤掲載の訂正依頼窓口を用意

## 掲載ポリシーの方向性

MYTOWN運営者の好みでイベントを選別しない。

「直方市内で一般参加可能」「情報源が確認できる」等の客観的基準を先に決める。

広告・有料イベントの場合はその旨を明確に表示。

違法・詐欺的・危険な内容等を除外するルールも必要。

## この機能がMYTOWNに与える意味

市政情報だけでは、政治に興味がない市民は毎日アプリを開かない。

イベント情報は日常的に開く理由になる。

```text
今日は何かある？
↓
MYTOWNを開く
↓
イベントを見る
↓
同じホームに道路工事・ごみ・行政情報・市議会もある
↓
生活のついでに町の仕組みが分かる
```

これはMYTOWNの「便利だから使い、気づいたら市政が分かっていた」という方向性と非常に相性が良い。

## 2026-09-02時点で確認した参考情報

- 直方市公式ホームページにはイベント・募集情報が随時掲載されている
- 直方市観光ポータルは独自にイベント・観光情報を発信
- 直方商工会議所にはイベントカテゴリがある
- ユメニティのおがたは独自に主催事業・イベント情報を掲載
- イオンモール直方には多数の独自イベントページがある
- チクスキには直方・鞍手を含むイベント掲示板と無料イベント投稿機能が既にある
- Instagram APIは主にInstagram Professional（Business / Creator）向けで、一般消費者アカウントを自由に取得する用途ではない

実装時は各サービスの最新利用条件・API仕様を必ず再確認する。

## 判断メモ

現時点ではP0候補。

理由：

1. 市政に興味がない人にもMYTOWNを開く日常的理由を作れる
2. 直方の情報分断という具体的な地域課題を解決できる
3. 既存の自動同期基盤を活用できる
4. 将来的に主催者・店舗・市民が参加するネットワーク効果が期待できる

ただし「全部自動取得」から始めると破綻しやすいため、主要5情報源のMVP → 主催者投稿 → SNS連携の順がよい。
